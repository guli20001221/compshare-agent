# RAG V2 全量预处理与知识库重建规范

状态：已实现并进入发布验证。基线为 GitHub `main` 的 `b5bbcd7568b02cab91b827ff2199b50bcb35646d`。

## 1. 范围与边界

本次重构只改变来源锁定、解析、清洗、图片/PDF 处理、chunk 边界、检索提示词、向量与发布产物。现有 `SearchKnowledge`、BM25/向量融合、`qwen3-reranker-8b`、引用校验、Agent 循环和答案合成逻辑保持不变。

运行时继续读取 `deploy/kb/stage2b_w0.jsonl`、`deploy/kb/external_w0.jsonl` 及其摘要命名的向量文件。V2 先生成不可变候选包，通过门禁后再提升到这些兼容路径。

## 2. 来源

内部知识库由以下公开来源构成：

- `compshare-docs` GitLab main，锁定提交 `8a81268e3d275d4767d045554680e7c5ddf82a9d`；
- 优云智算模型套餐 FAQ ZIP；
- ComfyUI 基础镜像 FAQ ZIP；
- 优云智算使用问题 FAQ ZIP。

外部知识库新增三个带 manifest 的来源快照：ComfyUI、数字人、语音/音频。没有原始文档的旧外部知识库不能重建，原 255 个 chunk 固定为 `legacy_external_lock.jsonl`，发布时标记 `legacy_unrebuildable=true`，不得把运行时输出反向作为下一次构建输入。

“锁定”不代表停止检索：这些 chunk 仍参与 BM25、向量召回和 reranker，也可重新生成 embedding。锁定只表示正文不能在没有来源证据时被清洗、重切或改写。其风险是无法自动跟随上游更新、无法验证陈旧结论，并可能与新来源内容重复或冲突。

旧快照必须逐步恢复来源：优先使用 `source_refs` 的文档族和路径线索，再用标题、命令、参数及正文中的独特短语搜索当前官方文档；找到后保存网页或仓库提交快照，逐条比对事实，重走正常预处理并替换对应 legacy chunk。不得仅凭搜索摘要改写旧正文。当前审计显示 255 个 chunk 中 253 个标记为官方来源、2 个为社区来源，保留 157 类来源前缀；前 20 类来源前缀覆盖 171 个 chunk，适合优先批量恢复。

每个 Git 提交、ZIP、旧 chunk 快照都记录 SHA256。来源变化必须产生新发布摘要。

## 3. 清洗原则

- 不做任何脱敏、掩码替换或秘密扫描式改写；公开 API Key 示例、URL、命令、错误码、参数值均保留原文。
- 只删除 front matter、脚本/样式、HTML 注释、重复空白等布局噪声。
- 不让 LLM 清洗或改写正文。
- 来源已经包含不可逆 `[REDACTED]` 占位符时，不猜测被删内容；将其作为来源缺陷排除并写入报告。
- 私聊、工单、后台页、临时签名链接不属于本公开知识库，在来源选择阶段排除，而不是入库后脱敏。

## 4. PDF、图片和链接

PDF 采用双通道：逐页提取文本，同时以 2 倍分辨率渲染每页并交给 VL。扫描页即使没有可提取文字，也能由页面图像补充内容。

图片采用：

1. 解析原图；
2. 主模型 `Qwen/Qwen3-VL-235B-A22B-Instruct` 提取说明、可见文字、控件和关系；
3. 主模型结构化输出失败时由 `Qwen/Qwen3-vl-Plus` 精炼重试；
4. 提取结果以图片说明、可见文字、控件和空间关系进入 chunk，供检索和回答；
5. 图片只作为构建期证据，不进入运行时知识库，也不提供原图链接。

原文已有公网图片和本地 GitLab/FAQ/PDF 图片都只在构建阶段下载或读取。最终发布不复制图片到仓库，`asset_refs` 为空，正文不写图片 URL。VL 结果必须保留命令、路径、错误码、模型名、数字、单位、按钮文字和界面关系；关键信息提取失败会阻断内部知识库发布。

二维码、群聊码、纯装饰图和无信息图不进入检索正文。来源快照未携带的相对图片、失效远程链接和 VL 最终失败会进入 `asset_report.json`，不得伪造说明。

## 5. Chunk 规则

先识别文档类型，再决定边界：

- 接口文档：完整接口是首选检索原子。正文不超过 4000 字符时整篇一个 chunk；超长时只按请求、响应对象、完整子结构或示例组拆分。
- 操作指南：不超过 4000 字符时整篇一个 chunk；超长时只按完整步骤组拆分，不拆开单个步骤、表格或代码说明。
- FAQ：每个完整问题与答案单独一个 chunk，不把相邻问题合并。
- 一般参考文档：按标题层级形成主题块，相邻从属章节可在 3400 字符目标内合并。
- 单个超长块才调用 `qwen3.7-max` 生成连续分组计划；模型不得改写正文。失败时按完整段落确定性打包。

每个 chunk 记录 `document_id`、`document_type`、`chunk_role`、`heading_path` 和来源引用。最大正文长度仍为 4000，兼容当前加载器。

## 6. 检索与模型角色

- VL 主模型：`Qwen/Qwen3-VL-235B-A22B-Instruct`
- VL 备用模型：`Qwen/Qwen3-vl-Plus`
- 语义边界：`qwen3.7-max`
- Embedding：`qwen3-embedding-8b`，4096 维
- Reranker：`qwen3-reranker-8b`
- 独立裁判主模型：`doubao-seed-2-1-pro-260628`；服务连续超时时允许同版本 `doubao-seed-2-1-turbo-260628` 复核，并在报告中记录实际模型。本次主模型连续两次超时，实际裁判采用 turbo。

检索问法由标题、标题路径、产品域和高价值自然问法构成。磁盘计费、Coding Plan、库存状态等真实回归问法必须进入发布门禁。Embedding 和 reranker 配置不变。

## 7. 可重复构建

`asset_lock.json` 固定每个图片引用的 VL 结果或缺件状态；`semantic_plans/` 固定每个超长文本的分组计划。锁指纹包含来源图片集合和模型配置，来源或模型变化时自动失效。

同一来源锁和模型锁连续两次构建必须得到相同 chunk 数和 LF 归一化 SHA256。向量文件必须满足 chunk ID 一一对应、4096 维、行数一致和摘要锁一致。

## 8. 发布门禁

- JSONL 字段完整、ID 唯一、版本一致、正文不超过 4000；
- 不含流水线生成的脱敏占位符；
- 最终 corpus 不含图片链接或发布图片资产；有信息图片必须转换为结构化 VL 文本；
- 内部必需本地图片或已下载图片的 VL 失败阻断发布；来源本身缺图单独报告；
- 主质量门禁使用 2026-06-26 至 2026-07-09 真实聊天中人工挑选的 50 个 RAG 检索问题；只提交单向哈希和分类，不提交用户原文；
- 旧 255 题只作为兼容性回归，不再作为检索质量结论；
- 真实问题中的 miss 必须逐条区分源文档缺失、检索缺口和裁判误判；未解决或未接受的源文档缺口会使候选保持待评审状态；
- 内外语料与向量能被当前 Go 加载器合并，chunk/向量严格双射；
- `go test ./internal/knowledge ./internal/tools ./internal/engine ./cmd` 通过；
- 独立裁判评测报告通过后才可合并。

## 9. 回滚

代码和数据在同一 PR 中原子发布。出现问题时回滚该提交即可恢复上一组 corpus、向量和摘要常量。紧急情况下可设置 `COMPSHARE_EXTERNAL_KNOWLEDGE=0` 暂停外部知识库，但这只回退外部数据，不改变 Agentic RAG 逻辑。
