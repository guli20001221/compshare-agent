# 上下文连续性去补丁化执行结果

状态：实现与组合验收完成
分支：`codex/context-depatching-v1`
基线：`codex/context-continuity-v2@7b7fd88a`

## 1. 已完成

### D1：统一上下文与回答契约

- 每轮只构建一次 `TurnContextView`，来源仍是已提交对话和 `SessionState`，没有新增第三套存储。
- Router、Agent 和直接 Renderer 都从同一轮次视图取得理解上下文。
- 所有确定性直接回答都包装为 EvidenceEnvelope；缺参数且已有完整历史时回到受限 Agent，不再按“这个、那个、还是、多少钱、呢”等词判断。
- `DispatchSpec` 同时登记执行方式、工具范围、回答契约和安全级别；删除第二份“需要上下文的意图”名单。

### D2：知识路径与提示收口

- 生产知识问答固定为 Agentic RAG；删除终端 RAG 生产分流、回退开关、孤儿补全函数和临时路由词表。
- 知识行为只由 `knowledge_turn_policy` 注入一次，Prompt Builder 按 section ID 去重。
- Agent 先读完整对话和已验证记忆；已有信息足以回答时可以不检索，需要新事实时自行组织独立可理解的 query。

### D3：知识答案核验收口

- 最终答案统一使用带出处的语义证明；引用标点不再决定答案生死。
- 删除数字、单位、否定词、中文分句和单位换算规则，以及对应的死代码和离线评分器。
- 无法证明时只允许一次基于同一证据的修复；仍无法证明则明确说明证据不足，不能谎称“知识库未覆盖”。
- “粘贴呢”真实脱敏记录及其完整上一轮已进入自动化回放；模型可直接使用前文正确回答，也可在需要时检索。

### D4：长期记忆收口

- 删除“就用、选择、决定、改成、确认”等关键词分类。
- 业务任务、实体、工作流结果和已验证知识由结构化事件更新。
- 被逐出完整问答只通过带逐字出处的语义压缩进入长期记忆；压缩失败保存少量未分类原文摘录，不猜测含义。
- 冷启动读取 61 个已提交问答对，使最老一对在新轮开始时进入摘要；摘要与本轮状态由持久轮次事务一并提交。
- 跨轮原始工具 JSON 被移除；实时价格、库存、状态和监控必须重新查询，避免热缓存比冷重建更陈旧。

### D5：凭证规则收口

- 凭证识别、字段判断和文本清理只由 `internal/guardrails` 维护。
- `security`、`sanitizer`、轮次协调、历史压缩和消息保存只调用公共接口，不再各自维护 AK/SK/token/password 正则。
- 保留不同边界的显示占位符，但识别规则是同一份。

### D6：组合约束与可观测性

- trace 新增有界元数据：实际上下文来源、回答契约、Prompt section、记忆更新来源和知识核验结果；不记录原始上下文内容。
- 安全阻断和账号能力阻断不再清除等待中的选择或任务；它们只阻止本轮回答/操作。
- 通用读取失败回到携带完整历史、但工具受限的 Agent；不会用一句无上下文罐头结束。
- 使用中的实例表确定性渲染和写操作确认仍保留。前者防止模型手写资源数据，后者是权限边界，不参与“是否传上下文”的判断。

## 2. 保留的确定性规则

以下规则没有删除，因为它们不决定是否向 Agent 提供上下文：

- 实例 ID、名称、序号、容量、时间窗等业务参数解析。
- 写操作动作识别、确认卡、目标可信度和“无卡启动”等安全检查。
- 越狱、跑题、人工客服等明确策略出口。
- 凭证、个人信息和输出泄漏清理。
- 工具白名单与只读/可写权限范围。

这些规则只能约束业务参数、权限或输出安全，不能清空会话、裁剪理解上下文或替代 Agent 的语义判断。
