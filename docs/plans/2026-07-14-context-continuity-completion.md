# 上下文连续性收口说明

## 目标

无论请求落到哪个进程、是否重连、是否发生缓存逐出、是否命中快速回答路径，系统都必须满足：

1. 已确认保存的对话和任务状态可以恢复。
2. 需要理解用户意图的组件能够看到足够的近期对话和长期摘要。
3. 快速回答不能因为绕过模型而忽略明显的上下文依赖。
4. 安全规则可以阻止危险操作，但不能静默删除上下文或把未保存结果伪装成成功。
5. 知识回答可以复用此前已经验证过的证据；只有确实需要新事实时才重新检索。

## 当前生产契约

- WebSocket 对话必须走持久化轮次协调器。一次回复只有在用户消息、助手消息和会话状态共同提交后才宣布完成。
- 同一会话同时只允许一个执行中的轮次；重试、断线和跨进程接管复用同一个轮次记录，不重复执行写操作。
- 每轮从数据库恢复已提交的完整问答对。模型看到最近 60 对完整问答和更早内容的语义摘要；路由器看到有界的近期问答和结构化任务状态。
- 快速回答需要上下文时，必须携带任务说明和证据，或回到受限的 Agent 继续判断，不得直接输出无上下文罐头。
- 知识问答允许直接使用此前已经验证的知识结论。需要新资料时，由 Agent 根据完整对话生成可独立理解的检索问题；最终答案在发送任何文字前做证据核对。
- 正式持久化路径没有 10 轮上限。旧上限只属于停用持久化协调器时的兼容路径，不得作为生产降级方案。

## 规则出口账本

| 规则 | 是否允许跳过模型 | 上下文处理 | 结论 |
|---|---:|---|---|
| 越狱、明显跑题、转人工 | 是 | 本轮问答仍保存；任务和已确认事实不清空 | 保留，属于安全或服务边界 |
| 账户余额、账单、发票等尚无可信接口的查询 | 是 | 保留历史和任务，不开放无关工具 | 保留，待专用只读能力接入后再放开 |
| 写操作确认、危险操作拒绝、目标不可信 | 是 | 待办和确认卡持久化；失败或拒绝不冒充完成 | 保留，属于操作安全 |
| 限流、调用预算、工具次数上限 | 可以 | 已经取得的答案或证据不得丢弃；会话状态继续保存 | 保留资源限制，禁止“花完钱再丢答案” |
| 会话状态版本过新 | 可以 | 只读回答并明确告知；原始状态绝不覆盖 | 保留，防止回滚毁数据 |
| 已知格式损坏 | 可以 | 明确告知并重置为可恢复空状态，然后落库自愈 | 保留，数据本身已不可读 |
| 任务或实例绑定过期 | 可以 | 只撤销执行授权，保留任务摘要和线索；执行前重新确认 | 保留，防止对旧目标误操作 |
| 知识证据不足或答案无法被证据支持 | 可以 | 保留问题、已验证的旧证据和拒绝原因 | 保留，不把无依据内容发给用户 |
| 诊断描述含糊 | 仅首轮可以 | 有完整历史时交给 Agent 结合前文判断 | 已修复原来的无上下文终止 |
| 历史监控缺时间范围 | 仅首轮可以 | 有完整历史时交给 Agent 从前文提取时间范围 | 已修复原来的无上下文终止 |
| 快速查询失败或要求补充信息 | 否，若已有完整历史 | 交给受限 Agent 解释、重试或追问 | 已修复原来的罐头终止 |
| 路由器报错、低置信或输出无效 | 否 | 不删除待办；由上下文裁决层决定继续、澄清或新任务 | 已修复“路由一抖就失忆” |

## 已封住的上下文遗失入口

- 先完成后保存、并发覆盖、跨进程双写、重试重复执行。
- 缓存逐出或进程重启后只恢复部分历史。
- 前端断线、刷新、双标签页后更换轮次或把未保存回复当成完成。
- 工具结果被截成损坏数据，或把局部结果说成完整结果。
- 任务帧因路由不确定、查询失败、用户拒绝或无关选择而被提前删除。
- 直接回答器、路由器、知识检索和最终知识回答只看当前短句。
- 已有证据的答案因为引用标点缺失被错误替换成“知识库未覆盖”。
- 未经证据核对的知识草稿先流到浏览器，随后才被服务端改成拒绝。
- 10 轮后静默换成空会话。

## 上线与验收门

代码层完成不等于生产已经完成。以下事项必须作为同一次发布验收：

1. 合并后端上下文分支和前端连续性分支，并应用数据库迁移 0005 至 0008。
2. 确认正式环境启用持久化轮次协调器；如果它不可用，应明确失败，不得静默退回旧兼容路径。
3. 用真实 WebSocket 网关验证短追问、刷新恢复、断线重连、双标签页并发、缓存逐出、服务重启和数据库故障。
4. 用真实历史记录中的上下文问题做小规模回放，至少包含“粘贴呢”、诊断续问、监控时间续问、已检索知识的直接续答和任务确认。
5. 验收同时核对答案正确性、是否保存、下一轮是否能继续，以及危险操作是否仍需确认；不能只看最终文案。

通过以上五项后，剩余工作才属于持续观测，而不是已知的上下文修复。
